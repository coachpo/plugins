# 初始化与维护项目文档和工作规则

审查只读，只报告事实、缺口和拟议的改动；请求初始化、维护或更新时才写入。只给出技能名、没有说是否写入时先按审查处理。

先确定写入范围。请求只提文档（含“整套文档”）时，只做项目文档部分，`CONTRIBUTING.md` 属于文档，各级 `AGENTS.md` 只读。只提项目规则时，只写请求范围内的 `AGENTS.md`。仅点名某份文件时限定到该文件。请求涵盖两部分时，先文档后规则；未限定部分时默认两部分都做。

在[多单元仓库](#多单元仓库)点名某个单元时，只写该单元内请求涵盖的文档或规则。维护文档时还可修复或补齐根文档指向该单元的入口和链接。链接改动不触发根文档的整篇整理或模板合并。根的其他内容和其他单元只读。发现跨层错位时，保留原文，列为拟迁移项。只读审查沿用同一范围，按层报告。

迁移、删除文档或原地改动标题、锚点前，先核对受影响的引用。改动本身或同步修复引用需要越出写入范围时，保留相应原文、路径和锚点，交接时列出拟改项及受影响的引用。

多个单元、模块或子树能独立取证时复用[仓库并行调查](../investigate-repo/SKILL.md)；先结束只读调查，再由主 agent 做获准的修改。

## 内容标准

在请求范围内，初始化和维护写入或改写的每份文档都用同一标准。只读审查也逐段检查，包括已有 ADR，列出拟删项和拟改项，将每个违规外部链接列为拟删项。固定位置齐全时仍要检查内容。

文档不复述代码、配置或 schema，也不规定实施细节。只保留以下内容，按实际需要写，不把类别当成章节清单。

- **目标与边界**：用途、要达成的结果和高层现状，模块与包的职责、相互契约、对外接口、外部约束、环境划分和明确排除的范围。
- **规则与决策理由**：授权和操作规则、工程约定、不变量、安全、隐私和数据约束，以及代码看不出的要求和理由。有依据时记录放弃的方案和取舍。
- **执行、故障恢复与回滚**：安装、运行、检查、迁移、发布和运维所需的前提、顺序、命令和验收方法，以及如何判断故障、恢复和确认恢复成功。
- **领域语义、已知限制与未决事项**：术语的确切含义、外部系统的硬限制或特殊行为、已知产品缺口、暂缓的决定和转入生产前必须完成的变更。
- **演进与兼容策略**：契约版本的含义、升级方式、迁移基线政策和组件发布顺序。
- **入口指引**：需要字段、端点、键名或常数时，说明以哪个文件为准，链接实际的源码、配置或 schema。涉及外部系统时，可链接其公开的官方文档作为权威来源。只有缺少机器可读定义且调用方确实依赖的契约细节，才在文档中直接定义。

逐段对照权威来源。纯实施细节删除；一段同时解释实现和约束、理由、限制或恢复方法时，只提取后者，按下表归位并保留原意。有效的非实施细节内容不丢弃。判不清时保留原文，在交接中列出疑点。约束索引引用的条文受下文的保护规则约束。

按链接类型判断外部引用，不尝试登录或打开会话链接。

- 可链接外部系统的公开官方文档、公开的法规和标准、规范、库和设计系统文档，以及项目自有的主机和代码仓库、本地开发地址。项目自己的代码仓库即使是私有的也可以链接，能读到文档的人已有访问权限。
- 不链接需要特定账号或权限的材料（如 AI 对话、artifact、设计工具文件或分享链接、私有文档、第三方平台的控制台或仪表盘页面）、Agent 或工具的会话和线程、临时预览或分享链接，也不引用仓库外的本机路径。
- 移除违规链接时，把它承载的决策依据、契约、规则或已知偏差写入相应小节。原句仅指向材料时整句删除。无法从材料取得事实时，去掉链接，保留文档原有陈述，在交接中列为疑点。仓库无法核实的外部理由保留并标注为未核实。

## 项目文档

盘点整套文档时，先核对根的五份固定文档和 ADR 目录，再查看按需建立的文件和其他路径上的文档，包括译本和受生成器管理的区域。

| 固定位置 | 内容归属与证据 |
| --- | --- |
| `README.md` | 项目用途、高层现状、经核实的快速开始和文档入口 |
| `ARCHITECTURE.md` | 模块和包的职责，以及模块之间、模块与外部系统之间的数据流。依据实现和调用关系核实，写到模块边界为止。链接各专题文档 |
| `CONTRIBUTING.md` | 贡献者共用的设计、实现、文档、验证与提交流程，项目确立的工程和业务规则、安全与数据约束及迁移基线政策。命令和约定从配置、测试入口或已确认的规则核实 |
| `CHANGELOG.md` | 按可核实的版本历史，只记用户能感知的变化，省去实现描述。提交日期不能证明发布日期 |
| `docs/adr/` | 有决策依据时记录背景、决策、原因，以及有据可查的放弃方案与取舍。当前实现本身不能证明当初的理由或备选方案 |
| `docs/operations.md` | 环境划分、部署与组件发布顺序、监控、排障、回滚与恢复。影响操作的外部限制和转入生产前必做的变更及验收写在这里。沿用旧手册而仓库无法核实的内容标注为未核实 |

| 按需建立的文件 | 内容归属与证据 |
| --- | --- |
| `docs/<专题>.md` | 契约专题只写调用方依赖的语义、不变量、外部系统限制、版本与兼容策略、恢复行为及权威来源入口。字段、端点、键名和常数按内容标准处理。领域术语另归术语专题 |
| `CONSTRAINTS.md` | 用户纳入管理的项目约束索引，以及没有其他出处的约束条文。由[项目约束管理](../constraint-manager/SKILL.md)按需建立和维护：本技能不创建它，不建占位，不增删条目，不改条目的状态和陈述 |

### 多单元仓库

单元是带独立清单、可以独立构建或部署的应用或包。仓库根目录之下有两个及以上单元时才启用单元层，按下表整理各单元的文档和跨层入口。否则只有根层，沿用上面的固定位置和按需文件，下文的单元层规则不适用。

| 文件 | 根 | 单元 |
| --- | --- | --- |
| `README.md` | 整体用途、现状、单元列表和文档入口；单元列表只写名称和入口链接 | 单元用途、现状、快速开始和单元文档入口 |
| `ARCHITECTURE.md` | 单元职责与排除范围、单元间契约与数据流、共享包和部署拓扑 | 按需记录内部模块边界与数据流 |
| `CONTRIBUTING.md` | 全仓共用的贡献流程和模板 | 按需记录贡献流程的实质差异，判据见[项目规则](#项目规则) |
| `docs/operations.md` | 实例或整体部署的开通、升级与下线，组件发布顺序，以及转入生产的条件 | 按需记录只涉及本单元的部署、排障与回滚 |
| `docs/adr/` | 跨单元决定 | 按需记录只涉及本单元的决定 |
| `docs/<专题>.md` | 跨单元术语和共享契约 | 本单元的术语、领域规则与契约 |
| `CHANGELOG.md`、`CONSTRAINTS.md` | 沿用上表规则 | 不建 |
| `AGENTS.md` | 授权、工作范围、环境、凭据、生产标识和跨单元命令 | 仅写符合[局部规则判据](#项目规则)的操作规则 |

先按适用范围定层级，再按内容定文件。两层仓库中，只涉及一个单元的内容归该单元，涉及多个单元、共享包或整体部署的内容归根。原文位置不决定去向。一次部署同时发布多个单元时（如一个单元的 Worker 托管另一单元的静态资源），这次部署的开通、升级和回滚流程属于整体部署。其他文件只链接正文，跨层不复述。跨单元流程受某个单元约束影响时，根文档保留一句操作要求，链接到该单元的正文。

### 文档归位

- 发现领域术语的业务定义，就归入同层的术语专题（如 `docs/glossary.md`）。一个定义也足以建篇；没有定义时不建。
- 产品缺口或暂缓事项，原文已写明选择及理由就是决策依据，迁入同层已有或新建的 ADR，保留取舍和重议条件。其余归同层 README 的现状部分。运维文档只收其中可执行的限制和步骤。

首次初始化空项目时，在根 `CONTRIBUTING.md` 写入完整模板，其余四个根文档建为占位文档，并创建空的 `docs/adr/` 目录（及必要父目录）。占位文档只含下面这一行注释，不加标题或示例：

```markdown
<!-- 空占位文档：尚无有证据的内容。写入内容时删除本行。 -->
```

专题文档不建占位，空目录里不放隐藏文件。Git 不跟踪空目录；仅当用户要求随 Git 保留时，先核实该仓库的占位惯例，不明确就询问，不能自行决定使用 `.gitkeep`。

初始化或维护整套文档时，补齐根的固定位置。除根贡献指南的模板规则外，有证据才填写相应内容；没有证据且根的固定文档缺失或为零字节，就写成占位文档。占位文档只建在根。有单元层时，整理各单元已有文档，缺单元 README 时只报告。对合规位置已有的文档也逐段应用[内容标准](#内容标准)，迁移保留内容并修复链接，标题、章节划分和顺序可按需调整。若目标被不相容的文件类型占用，先报告冲突，不强制覆盖。无历史证据时新建的版本记录保持为占位，不补写 ADR。

ADR 放在所属层的 `docs/adr/NNNN-<slug>.md`。编号全仓唯一，新 ADR 取全仓下一个空号。已有编号冲突只报告，不自行改号。已有 ADR 按需在本层改名、归位，只有适用范围与所在层不符时才跨层迁移。即使路径已合规也逐段检查。保留背景、决策、原因、原有的放弃方案与取舍，删掉可从源码查到的实现描述，提取其中的约束或理由。删减不得改变决策含义和结论。决策日期不可核实就不写，仓库无法核实的外部理由保留并标注。被 `CONSTRAINTS.md` 引用的条文按约束索引规则保留并报告。

按层判定旧文档。单元内处于本层合规位置的文档留在原处维护。除下列例外，本层合规位置之外有人维护的文档在本层归位，只有适用范围与所在层不符的内容才跨层迁移。旧文档逐段按内容标准取舍。设计与代码组织规则、允许或禁止的变更等贡献约定写入相应贡献指南的小节；在根指南中接在模板条款之后。部署事实归同层运维文档，能识别生产的对象同时按[生产标识](#项目规则)列入根 `AGENTS.md`。确认应保留的内容均已归位后，删除旧文档原件并修复链接。归属或有效性不明的段落先留在原处并询问。

带独立清单的应用或包，其 README 保留在原目录，不要求能独立构建或部署。启用单元层时，范围内的单元 README 作为入口按内容标准整理。以下不算旧文档：固定位置文档的译本、许可证、约束索引 `CONSTRAINTS.md`、Git 子模块自己的 README，路径由仓库之外的平台或工具约定的文件（如 `.github/` 下的模板、`CODEOWNERS`、`SECURITY.md`），以及各级 `AGENTS.md`、`CLAUDE.md` 等宿主指令文件（按[项目规则](#项目规则)一节处理）。同步更新仓库代码、测试、脚本和 CI 对旧路径的引用。被断言的契约或规则原样迁入新位置；若断言本身要求文档复制实现，保留并报告冲突，不削弱检查。拿不准某个路径是否由外部工具约定时，说明依据并询问。

各层 `docs/` 下已有的专题文档也逐段筛选。保留内容属于同一契约、领域规则或术语主题时沿用该文档；混合主题的内容分别归位，删尽实施细节后没有专题内容就撤掉该文件。受影响的引用都能在本次范围内修复时，移除从旧文档继承的章节编号，同步修复锚点和交叉引用。运维子目录（如 `docs/operations/`）并入同层的 `docs/operations.md`。

根 `AGENTS.md` 与 `CONTRIBUTING.md` 的模板适用范围和合并方式见[模板](#模板)。用户要求保留的文档留在原处，需要时从固定结构引用。要变更受生成器管理的区域的权威来源，先说明涉及的路径和影响，请用户确认。只审查时只报告拟议的取代和拟舍弃的内容。

项目有约束索引时，被它的 `Source` 或 `Also in` 引用的条文在取代、迁移、拆分、重组、改名或去掉章节编号时保持含义不变，并在同一次改动中更新索引里指向它的链接。拟舍弃或改写的内容是索引中的现行约束时，不舍弃、不改写，报告后交给项目约束管理的变更流程。只审查时只报告受影响的条目。

从各层的 README 给本层有实质内容的文档提供入口；已有入口可用就沿用，不为占位文档添加导航，也不因空项目已有贡献模板而填充 README。再次运行不重复追加规则或事实；结构和内容均合规且没有新证据的文档保持原样。专题文档一个主题一篇，用小写连字符命名，已有文件不符时改名并修复链接。每篇从同层的 `ARCHITECTURE.md` 链接，README 可沿用这个入口。单元层缺少架构文档时，从该单元 README 链接专题。仅在启用单元层时，从根 `ARCHITECTURE.md` 链接本次范围内的单元入口，从根 `CONTRIBUTING.md` 对应小节直接链接这些单元保留或新建的贡献指南。根架构文档的入口只列单元入口，不逐篇罗列单元专题，单元专题由该单元的架构文档或 README 索引；正文需要时仍可链接单元文档的具体段落。

检查零散进度文件（如 `PROGRESS.md`、`NOTES.md`）和其他文档里的进度段落。任务进度、会话记录和临时 TODO 列为删除候选；其中长期有效的限制、产品缺口、暂缓决定和生产前置条件按上表归位。发现遗留的 `.agent-work/` 目录只报告，不删除其他任务的工作目录。

## 项目规则

本节的写入只用于包含项目规则的请求。只维护文档时，发现根规则缺少生产标识等问题也只在交接中说明。

开始前读现有根规则、相关祖先和子目录规则，包括可能遮蔽它们的宿主覆盖文件；区分仓库里存在的文件和本次宿主确实加载的指令。不要修改覆盖文件、用户级配置或指令。Claude Code 在工作目录或其上级存在 `CLAUDE.md`、`.claude/CLAUDE.md` 或 `CLAUDE.local.md` 时默认不再读取 `AGENTS.md`，也不读取 `AGENTS.override.md`；发现这类文件时在报告中指出哪些宿主读不到哪些规则。

递归查看仓库内有人维护的模块、清单、脚本、CI、生成边界和文档，区分共享流程和局部例外。清单里有命令，不代表当前可用：核对执行目录、引用的脚本和输入是否存在；缺前提时报告缺口，不把它列为可用的验证步骤。不要只检查当前目录或为依赖、构建产物逐目录写指南。

初始化时按需核查以下线索；它们是候选检查项，不是输出提纲。不固定 `AGENTS.md` 的标题、字数或章节。

- 目录结构：哪些路径是修改入口，哪些是生成产物？不必罗列整棵目录树。
- 常用命令：从清单、脚本和 CI 核对构建、本地运行及验证入口，留意工作目录和前置条件。
- 风格工具：从配置和实际调用确认格式化器、lint 工具及其适用范围，不复述工具已执行的每条规则。
- 测试：核对测试入口、用例放置与命名，以及项目实际要求的检查；不推定覆盖率门槛。
- 提交和 PR：核对贡献指南、PR 模板和自动检查；Git 历史可佐证惯例，但个别提交不能确立政策。
- 生产标识：项目有生产部署且有证据时，在根文件按名称列出能识别生产或真实账号的对象：数据库和其他数据存储（名称、实例或保存连接串的变量）、部署目标（账号、项目、服务名）、触发生产部署的分支、生产域名，以及生产或真实账号密钥的变量名或文件名。不写密钥值。每项取自已核实的配置、CI、现有文档或用户说明，未核实的标注出来；不声称清单穷尽。仓库已有源码、清单或部署配置，却找不到生产部署的证据时，写明“尚无生产部署”是工作假设以及什么证据会推翻它，并列出已知的远程非生产目标。仓库里还没有可部署的内容时不写这一条。

有已知的转入生产前必做事项时，在根 `AGENTS.md` 的生产标识工作假设中写明转入生产的条件，链接运维文档中的变更和验收步骤。若任务只覆盖其中一份文件，另一处所需改动仅在交接中报告。

根 `CONTRIBUTING.md` 是唯一带模板的贡献指南。只有启用单元层，且单元贡献流程符合下文的局部规则判据时，才保留或新建单元指南，不复制模板。不满足判据的贡献约定应并回根指南；根正文不在写入范围时，保留原文并列为拟迁移项。

除模板条款外，只补充会改变 Agent 操作的项目规则。设计、兼容与迁移、文档、测试要求、界面文案、提交与 PR 格式，以及贡献者须遵守的产品与业务约束属于贡献指南；需要时链接到项目已有的对应小节，只补充影响当前操作的入口或局部例外。不复制贡献政策，不为去重改动另一份文档，也不为尚不存在的目标造链接。

补充项目规则时，全仓通用的写根文件。授权、环境、凭据和生产标识的操作规则只写在根。只在一个子树与上层有**实质差异**且有证据时，为它写局部规则：构建入口、验证命令或生成文件处理不同，或者有该子树特有、只读父级就会违反的约束。判据是这个问题：“只读父级，执行者会在这里做错什么？”每条局部规则都要能回答它，写成一句指出具体错误的操作规则，细节链接到架构文档或贡献指南；没有具体答案就不新建子文件。约束只在该子树内成立才写进子文件；全仓都成立的写根文件或贡献指南，一两句就能说清的差异也并回根文件。子文件里的一句操作规则不算复制贡献政策，但理由和细节留在它链接的文档里，链接目标也可以是专题文档。单元局部规则可链接本单元的文档。实现描述、目录清单和对父级的复述不写进子文件。共用流程不拆成多份。已有子文件也按同一判据整理：复述父级的条目删除；答不上这个问题的其他条目并回根文件，或迁到它们该在的文档；整份都答不上的子文件，内容归位后删除。规则换位置不算删除规则，有效性存疑的条目仍按下一段请用户确认。已满足判据的子文件不为统一格式而改写。

找不到佐证不等于人工约束失效。现有规则与仓库事实不符或有效性不明时，说明证据并请用户确认，不自行删除。其中已收录进约束索引的条文，本技能不改它的含义，也不改条目状态，是否变更交给项目约束管理。指出 `AGENTS.md` 中混入的任务进度、会话记录和临时 TODO；只在获授权的清理范围内删除。

## 模板

根 `AGENTS.md` 采用[根规则模板](references/AGENTS.template.md)，根 `CONTRIBUTING.md` 采用[贡献指南模板](references/CONTRIBUTING.template.md)。仅当目标文件整篇属于本次维护或初始化范围时，才按[模板写入与合并](references/template-merge.md)处理：缺失或零字节时全量写入；非空时合并全部非冲突规则，冲突逐条询问覆盖还是跳过。若只获准补入口而根模板目标缺失或为零字节，只报告缺口。不按仓库情况筛选模板规则，不向子目录复制根模板。项目专有规则写在哪里，也按该文件的规定。

模板不授予操作权限。不要寻找或复制用户全局模板，也不要把个人授权、凭据值或偏好写入仓库。

## 记录用户确立的规则和决定

用户要求记录本次或此前对话中明确确立的规则或决定时，逐项按[层级和内容](#多单元仓库)确定文件。同一请求中的产品职责、数据保留或权限模型等决定可以分属根和单元。只在单元内成立的领域规则写入单元专题文档。能确定位置就直接归位。适用范围不明时，只问涉及哪些单元或是否适用于全仓。用户要求把决定纳入约束管理时，交给[项目约束管理](../constraint-manager/SKILL.md)。记录规则或决定时，本技能不创建、不修改 `CONSTRAINTS.md`。

从用户的纠正或一次性任务指令归纳出的只是候选：列出候选及其依据，用户说写入后再写。Agent 操作规则写入其适用层级的 `AGENTS.md`；项目的设计、开发和评审政策写入相应贡献指南，`AGENTS.md` 里只写简短的操作规则并链接过去。请求只覆盖文档或只覆盖规则时，属于另一部分的内容只报告，不写入。与现有规则冲突时报告冲突，不自行取舍。

## 核对与交接

在本次范围内按层核对文件和 ADR 目录。启用单元层时，核对范围内的单元入口和单元贡献指南分别由根架构文档和根贡献指南直接链接。逐篇确认专题可从同层架构文档到达，单元没有架构文档时核对其 README 入口。解析相对链接及其锚点。按原文逐段与差异对照，确认术语和未决事项已归入指定位置。对删掉的每项实施细节，打开权威文件确认仍可查到；对提取的每条约束，核实目标小节和含义。旧文档应能对应到迁入位置、删除依据或保留原因。核对命令，搜索代码、测试、脚本和 CI 中残留的旧路径，运行断言了迁移内容的检查。有约束索引时，核对现行条目的 `Source` 和 `Also in` 仍指向原条文。规则部分按根到叶复读，核对路径与命令、重复规则及新建子文件的局部差异。

按类型核对剩余的外部链接均属允许类别。交接时逐项列出“完整原链接或路径 → 保留事实的文件及小节”或“完整原链接或路径 → 整句删除”。只读审查按同一格式列出拟删链接。

交接以实际差异为准，迁移逐项列出“原路径 → 层级 / 文件 / 小节”。逐项给出“删掉的实施细节 → 可查到它的文件路径”和“改写后保留的约束 → 目标文件及小节”。混合段落的删减和保留分别列明，已有 ADR 同样核对。只读审查按层用相同格式列拟删、拟改项和拟归入的位置。其余按实际情况列出新建占位、实质更新、其他舍弃内容及原因、保留的例外（包括受索引保护的 ADR 条文）、规则变化、证据与待确认项。验证日志和调查记录留在交接中。
